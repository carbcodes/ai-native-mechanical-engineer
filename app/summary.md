# app/ summary (Phase 0 shell)

**Built.** A SwiftUI macOS 14 app as a Swift package (`app/Package.swift`, executable `Mechy`, one dependency: Yams). There is a welcome screen with new/open/recent projects; New runs `mechy init <dir> --example tennis-catcher`. The project window has a file-tree sidebar and a drafting-sheet canvas: a dot and node grid you can pan and zoom, with panels you can move, resize and close. The toolbar adds panels and runs Build CAD, Run catch sim and Run agents. A slim agent bar shows status chips and has one request input, which writes `inbox/<ts>.md` and runs `mechy plan`. Panels: Inspiration (drop files, images or links), CAD (three.js line drawing or shaded view, variant tags), Options (cards; click writes `chosen`, the tweak box writes `feedback`), Questions (numbered note boxes that write `answer`), Sim (big catch rate with a bar against the target, failure chart, plots, video), Tasks (live board), and Docs (QuickLook). The style follows `docs/architecture/ui-style.md`; every token is in `Theme.swift`.

**Structure.** `App/`, `Theme/`, `Models/` (lenient contract mirrors), `Services/` (EngineClient, EngineLocator, ProjectSession, DirectoryWatcher + EventTail, YAMLPatch), `Views/` (Canvas, Panels, bars), `Resources/viewer/index.html`, and `Tests/`.

**Unverified.** Nothing has been compiled, because this machine has no Swift. The YAMLPatch logic was checked through a Python port against PyYAML. The viewer JS passed a syntax check, and its three.js paths were confirmed against the npm tarball. README lists the APIs to check first.

**Contract changes proposed.** The `inbox/` folder for user requests, and a `links.yaml` entry shape `{url, title?, added}`. Env vars `MECHY_PROVIDER`, `MECHY_CLAUDE_BIN` and `MECHY_CODEX_BIN`. The order of `--project/--json` relative to the subcommand needs to be pinned down. The app keeps a cache in `.mechy/viewer/`.

**Next.** Compile on a Mac and fix errors. Add scroll-wheel pan, CAD dimension lines, and dashed ghosts of unchosen variants.

## Changelog

**2026-10-24 — part colors, motion sim, electronics panel, chat dock** (compiled and run on macOS)

- *Part colors* (viewer). Each printed/structural part gets its own hue; motors share graphite, pulleys aluminium. Line mode fills with a light tint under the ink edges; shaded mode uses the full color. A legend lists the parts (multi-primitive meshes are grouped back to their node). Hovering a part or legend row outlines it in accent and labels it. This is a deliberate break from the monochrome sheet: parts must be told apart.
- *Motion sim* (viewer + CAD strip **Simulate**). The arm loops a demo routine (reach, pick, swing, place, raise) with minimum-jerk moves. A bar gives play/pause, Home, speed (1×/2×/0.5×) and four joint sliders; dragging one pauses and poses that joint. It is kinematic only. A sim replay takes over the joints while it plays.
- *Electronics panel* (`PanelKind.electronics`, in the default sheet in place of Tasks). A wiring diagram is drawn from hw/drivers.yaml + hw/motors.yaml (`HardwareSpec`): supply → bulk capacitor → CNC Shield power in → X/Y/Z/A A4988s (step/dir pins, Vref) → base/shoulder/elbow/wrist motors (coil pairs), the Uno under the shield, USB, and limit switches. Below it are the settings (driver current, Vref for R100 and R068 sense resistors, microstep jumpers, estimated supply draw) and a bring-up checklist. New optional hw keys: `shield`, `power_supply`, `bulk_capacitor`, `heatsinks`, motor `model`.
- *Agent activity on panels.* While an agent of the matching role (or an engine command that writes there) works on a panel, its frame turns accent and the drag strip becomes a status line with a pulse ("CAD agent · building forearm", or a %).
- *Chat dock.* The request box moved out of the bottom bar into a centred, larger multi-line composer (Return sends, Shift-Return adds a line). Above it are the last request (History expands to 8 from inbox/ and inbox/done/) and one Mechy line ("Working on CAD and simulation…", questions/picks waiting). Individual subagents are no longer listed in the bar; one "N agents working" chip remains, and the Tasks panel still shows each one.

**2026-10-24 — intake cards, PDF docs panel, design/chosen, Make it** (written on Linux, not compiled)

- *Inspiration digests* (`Models/IntakeModels.swift`, `Views/Panels/InspirationPanel.swift`). Dropping or pasting a YouTube/web link, or dropping a video, image or saved .html page, runs `mechy intake add <src> --project <p> --json` straight away. Each source gets a card with a spinner and the engine's progress message; a failure shows the error in a red mono line with Retry and ×. An image from outside the project is passed by its path (the engine keeps only an EXIF-free copy) and is copied in only if the intake fails; videos and .html are copied into inspiration/ first. Each digested `inspiration/<slug>/source.json` shows as a card: contact sheet (else first keyframe, else the clean image), a duration box, the title, and a dashed tag such as "12 FRAMES · TRANSCRIPT". Clicking opens a popover with the kind/length/licence, the link, a keyframe strip (time labels; a click opens the system Quick Look panel, and the arrow keys page through), Contact sheet / Transcript / Page text buttons, warnings, and `inspiration/notes/<slug>.md` rendered block by block (headings, bullets, tables, code, and inline Markdown through `AttributedString(markdown:)`). Raw files, links.yaml entries (`digested:` or a matching URL) and notes that belong to a digest are no longer drawn twice. Items that are not digested get a dashed frame, a "Not digested" label and a context-menu "Digest" item. **Digest all** runs `mechy intake all`.
- *Docs panel* (`Views/Panels/DocsPanel.swift`). It lists docs/<variant>/*.pdf grouped by variant, with PDFKit first-page thumbnails (loose files at the top of docs/ come last; the .typ, .data.json and img/ sources are left out). Below 440 pt of width the list becomes a thumbnail row. PDFs show in a `PDFView` with a page bar: ◀ "Sheet n / N" ▶ (⌘← / ⌘→), Print (system panel at 100% scale, since the sheets are true to scale), Open and Reveal. Other files still use QuickLook. The strip has variant tags and **Build docs** (`mechy doc build <v>`), **Print version** (`--print`) and **Firmware** (`mechy control gen <v>`, then control/<v>/ opens in Finder; right-click picks `--board uno_cnc` or `mega_ramps`). Each button shows a spinner while its command runs. When a build finishes, its newest PDF is shown.
- *Options pick the variant.* Picking an option still writes `chosen` to the YAML. If the option id is also a `design/<id>/` folder, the app writes `design/chosen` too and shows that variant in the front-most CAD panel (it adds one if there is none). The card then says "design/chosen = v2".
- *Make it* (`Services/MakeItPipeline.swift`, agent bar ▸ MAKE IT menu, Engine ▸ Make It ⇧⌘M). It runs Build CAD → Run sim → Generate firmware → Build docs for design/chosen (else the variant on screen), one after the other, and stops at the first failure. Progress chips in the agent bar: done ones solid with a check, the running one in accent with its message and %, pending ones dashed, the failed one red with the error (its log is in the tooltip, and the context menu has Copy log), and skipped ones faded. There is a stop button while it runs. When every step passes, the build guide opens in a Docs panel. The menu also has each step on its own, Build print docs, and Digest pending inspiration. The separate run chips of pipeline steps are hidden. Engine menu: Build Docs (⇧⌘D), Build Print Docs, Generate Firmware, Digest Pending Inspiration.
- `EngineClient`: `intakeAdd`, `intakeAll`, `docBuild(printVersion:)`, `controlGen(board:)`, `activeRun(prefix)`. `buildCAD` / `runCatchSim` take an optional completion. Static calls inside `ProcessTree`'s escaping closures are now qualified (`ProcessTree.descendants`), so the compiler cannot ask for an explicit `self`.
- Compile-safety pass over the code written after be7a132 (EngineClient, ProjectSession, Parts, Tasks, CAD replay, PanelFrame, SimPanel, tests): no definite errors found. Ternaries passed to `frame(maxWidth:)` now name `CGFloat.infinity` explicitly.
- Tests: `IntakeModelsTests` (source.json reading with a missing keyframe, broken JSON, duration format, Markdown blocks, card titles).

**2026-10-23 — sim theater, parts panel, run/stop agents** (written on Linux, not compiled; viewer JS tested in headless Chromium)

- *Sim theater in the CAD viewer* (`Resources/viewer/index.html`, contracts §11). `window.mechy.loadReplay(fileURL, stamp, title)` reads `sim/<task>/replay.json` with XHR. If WebKit refuses the file URL, the page posts `replayFailed` and Swift re-sends the file with `loadReplayBase64`, once per replay. The page finds the GLB nodes `turntable`, `upper_arm`, `forearm` and `hand`, then sets each one to `R(axis, q − rest) · restQ`. The axis comes from replay `joint_axes`, else the node's `extras.axis`, else the contract default, and it stays fixed in the parent body. `rest` is the twist of the node's own rest rotation about that axis, which matches `engine/mechy/cad/glb.py`: it writes the ready pose as `R(axis, rest)`. A mismatched replay `rest_q` therefore cannot skew the arm. Node extras `q`/`rest_q` or a replay `glb_q` override it. Checked in headless Chromium: with a non-zero rest pose and a deliberately wrong `rest_q`, the hand origin matches forward kinematics to 1e-16 m. It also plays the real engine `arm.glb` (belt_arm v1) with a real `catch-v1/replay.json`, and the ball ends in the cup. On top of the arm it draws the 67 mm ball (paper fill with an ink outline), the travelled path (solid, grows as the ball moves), the predicted path (dashed, muted) and the catch point (a small accent cross drawn through the model). Controls: previous throw, play/pause, next throw, a scrub slider, the time, and a 1×/0.25× speed button. An outcome tag shows CAUGHT in green, or the failure (BOUNCED OUT, OUT OF REACH, …) in red. Other tags show the task, the throw id and position (n/N) and the live joint angles. Keys: space plays or pauses; `[` and `]` change the throw. The throw loops after a 1 s hold. If the GLB has no joint nodes, the model stays static, the ball still plays, and a dashed note says "Static model: no joint nodes in arm.glb (rebuild CAD)". Closing the replay restores the rest pose.
- *Replay from the app.* SimPanel has a **▶ Replay** button for the selected report (it is disabled, with a tooltip, when there is no replay.json). The report menu marks reports that have a replay, and task tiles have a "Replay sim …" context item. The button opens the front-most CAD panel, or adds one, on the sim's variant. A new `PanelState.replay` holds the task id and is optional, so old layouts still decode. While a replay plays, the CAD strip shows an accent "REPLAY <task> ×" tag. Picking a different variant clears the replay.
- *Parts panel* (new `PanelKind.parts`, Sheet ▸ Add Parts). It reads `design/<v>/print_list.csv` and `bom.csv` with a small RFC 4180 reader (`Models/PartsModels.swift`). Column names are matched leniently, and bad numbers never trap. It shows totals: estimated cost (purchased parts plus filament at $20/kg), purchased cost and line count, and printed grams, pieces and filament cost. Below are two compact tables with total rows. Clicking a printed part previews its STL in a Docs panel (QuickLook); the context menu has Show in Finder. **STL folder** opens `stl/` in Finder.
- *Run agents* now runs `mechy run --jobs 2 --project <p> --json`, with `MECHY_PROVIDER` taken from Settings as before. A Run/Stop button sits in the agent bar, the Tasks panel strip and the toolbar. There is also Engine ▸ Stop Agents (⌥⌘.). Stop freezes the scheduler (SIGSTOP) and lists its process tree with `ps`. It sends SIGTERM to the whole tree, resumes the root, and after 3 s sends SIGKILL to anything still alive, including children started meanwhile. The run then ends as "Stopped", not as a failure. Quitting the app sends SIGTERM to every running tree. stdout events of app-started runs now reach `session.events` (`EngineClient.onEvent` was never wired before). They are de-duplicated against the `events.jsonl` tail, and task start/done/fail events trigger a reload. The Tasks panel shows a feed line: state, elapsed time, provider, jobs, and the last 3 events. Live tiles show the latest `agent.output` text.
- Tests: `PartsCSVTests` (quoted fields, CRLF, doubled quotes, totals, a "nan" quantity, PanelState decoding without `replay`).

**2026-10-23 — layout fit, sim chart, appearance, option placeholders** (written on Linux, not compiled)

- *Sheet fits the window.* The default layout is now computed from the measured canvas size (`CanvasLayout.initial(fitting:)`): three columns sized to the visible width, zoomed out (down to 40%) when the window is smaller than 1120 x 660 pt. On launch, a new project gets this layout; a saved layout that runs off the window is fitted; the old fixed default (Sim/Tasks at x = 956) is replaced. View ▸ Fit All Panels (⌘0), Zoom In (⌘=), Zoom Out (⌘-), Actual Size. Reset Layout uses the current canvas size.
- *Zoom controls moved* from the bottom-right of the sheet into the agent bar (right end), so nothing floats over panels. The "Scale x:1" tag was removed (the percentage shows the same).
- *Sim failure chart* is now hand-drawn horizontal bars (no Swift Charts): label column, bar scaled to the largest count with 40 pt kept free for the value, so every count (e.g. "Bounced out 57") is visible and nothing overflows. Header shows "of N throws". The catch-rate block and stats stack vertically in narrow panels (`ViewThatFits`).
- *Appearance:* System / Paper (light) / Graphite (dark) in Settings ▸ Appearance and View ▸ Appearance. Stored in UserDefaults (`appearance`), applied app-wide with `NSApp.appearance`. The CAD viewer gets it as `window.__mechyTheme` (document-start user script), `window.mechy.setTheme(...)` on change, and `WKWebView.appearance`.
- *Options:* an option with no thumbnail on disk and no stats shows a dashed "Not built yet" card (a Build button if it names a variant); options with a thumbnail but no stats say "No stats yet"; a set with no options shows a dashed note. `summary` / `description` fields of option entries are shown in small mono text.
